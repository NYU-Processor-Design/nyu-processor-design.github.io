## Week of 5 October 2026

### Lab 3: SystemVerilog Verification and FIFO Design

- [My Onboarding Repository](https://github.com/xal215-cpu/processor-design-onboarding)

This week, I learned how to verify SystemVerilog designs using self-checking testbenches. I wrote directed and randomized tests for an accumulator and a FIFO.

For the FIFO, I tested reset, normal reads and writes, full and empty conditions, pointer wraparound, simultaneous read/write, and rejected operations when full or empty. The FIFO uses memory, read/write pointers, and a count to track how many entries are stored.

I also used randomized testing and a reference model. The reference queue kept track of the expected FIFO data, which made it easier to compare the DUT output with the correct result over many random cycles.

I had some trouble with Verilator width warnings and accidentally entered SystemVerilog code directly into the Terminal. I fixed the width issue by using a wider temporary random variable and then selecting the needed bits.

All accumulator and FIFO tests passed with Verilator.

### Instruction Immediate Module

This week, I started working on the Instruction Immediate module (`instr_imm.sv`) for the processor core. I was assigned to the implementation issue and followed the team's Git workflow by forking the main repository, creating a feature branch, and working on the module there.

Before writing the module, I learned how the different RISC-V immediate formats work. I learned how to reconstruct I-type, S-type, B-type, U-type, and J-type immediates from different parts of the 32-bit instruction. I also learned how sign extension works and why branch and jump immediates have a zero as their least significant bit.

For the implementation, I used the opcode to determine the instruction type and funct3 to handle the special shift-immediate instructions. The module now generates the 32-bit immediate for the supported instruction types.
