## Week of 5 October 2026

Project Work:
  * [Processor Design Onboarding Repo](https://github.com/Vinn1234y/processor-design-onboarding): Completed Lab 3 (Verification, Reference Models, Accumulator testbench, and Parameterized Synchronous FIFO RTL + Testbench).

**Tests Written:**
For the 8-bit accumulator (`accumulator_tb.sv`), I wrote modular verification tasks (`check_sum` and `apply_and_check`) that drive inputs on the falling clock edge and verify outputs after the rising edge. My directed tests verified synchronous reset, single addition, multi-cycle accumulation, holding the sum for `enable = 0`, resuming accumulation when re-enabled, and 8-bit unsigned overflow wraparound, followed by 100 cycles of randomized testing against an `expected_sum` reference variable. For the synchronous FIFO (`fifo_tb.sv`), I wrote 10 directed test cases covering reset (`empty = 1`), single write/read round-trips, multi-value FIFO ordering, `full` assertion at `DEPTH = 4`, rejecting writes while full, draining to `empty`, rejecting reads while empty, pointer wraparound, and simultaneous accepted read/write, followed by 200 randomized cycles verified against a SystemVerilog dynamic queue (`expected_queue[$]`) with a `#100us` watchdog timer.

**How the FIFO Works:**
The parameterized `fifo` module (`WIDTH = 8`, `DEPTH = 4`) uses an unpacked memory array `logic [WIDTH-1:0] mem [0:DEPTH-1]`, read and write pointers (`rd_ptr` and `wr_ptr`) that were sized to `$clog2(DEPTH)` bits that can wrap around at the end of the power of two memory, and an occupancy counter `count` that was sized to `$clog2(DEPTH + 1)` bits. Combinational logic sets `empty = (count == 0)` and `full = (count == DEPTH)`, and determines accepted operations before the clock edge (`do_write = wr_en && !full`, `do_read = rd_en && !empty`). On each rising clock edge, an accepted write stores `wr_data` at `mem[wr_ptr]` and increments `wr_ptr`, an accepted read latches `mem[rd_ptr]` into `rd_data` and increments `rd_ptr`, and `count` increments on write only, decrements on read only, or remains unchanged when neither or both operations occur simultaneously.

**Bugs and Edge Cases Encountered:**
When compiling `accumulator.sv` and `accumulator_tb.sv` with Verilator, I initially hit a `%Warning-TIMESCALEMOD` compilation error because `accumulator_tb.sv` included `` `timescale 1ns/1ps `` while the `accumulator.sv` did not. Adding `` `timescale 1ns/1ps `` to the top of both of the RTL and the testbench files helped to fix the issue. I also made sure that `do_write` and `do_read` were evaluated using `full` and `empty` before the clock edge so that writes while full and reads while empty are rejected even if the opposite enable is asserted on the same cycle.

**How Randomized Testing and the Reference Model Helped:**
While directed tests verified the specific corner cases I manually planned for, combining `$urandom_range` stimulus with software style reference models (`expected_sum` for the accumulator and the dynamic queue `expected_queue[$]` using `.push_back()`, `.pop_front()`, and `.size()` for the FIFO) automatically verified hundreds of back to back read/write interleavings, repeated pointer wraparounds, and flag transitions without having to duplicate the RTL pointer hardware logic inside of the testbenches.
