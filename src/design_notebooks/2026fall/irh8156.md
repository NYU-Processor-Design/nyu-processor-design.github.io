## Week 1 (Sep 22-28)

- Attended the second team meeting
- Looked through the given textbook
Notes: 
- Datapaths are the components that store, move, and operate on values (registers, ALU, etc)
- Control unit decodes the instruction and tells components what to do
- Different instructions reuse much of the same hardware
- Multiplexers make hardware sharing possible
- The clock separates calculation from stored state
- Control logic can be designed systematically (with a truth table)
- One instruction per cycle does not necessarily mean a fast processor

## Week 6 (Oct 26-Nov 2)

- Claimed issue #1 for the ALU implementation and set up a fork and the `alu-implementation` branch in VS Code.
- Completed the ALU implementation and Level 1 testbench with AI assistance. The module supports ADD, SUB, SLL, SLT, SLTU, XOR, SRL, SRA, OR, AND, and JALR address calculation, along with the zero flag.
- The implementation uses the lower five bits of the shift operand, distinguishes signed and unsigned comparisons, and clears the lowest result bit for JALR. Arithmetic results wrap to 32 bits, and undefined operation codes return zero.
- Installed Icarus Verilog and Verilator through MSYS2 and ran the project checks. The ALU passed 6,928 directed, boundary, and deterministic randomized test vectors checking both the result and zero flag. These included overflow, signed comparisons, and every shift amount.
